# private_AI-JAM-sales

代理店売上管理シート(Google スプレッドシート)と、SBペイメントサービスが発行する
収納明細書(PDF)を自動で突き合わせる、Google Apps Script (GAS) 製のツールです。

## 何をするツールか

1. 指定したGoogle Driveフォルダにある収納明細書(PDF)を読み込み、テキスト化する
2. PDFから「集計期間」「決済処理件数」「決済処理金額(合計)」「お振込金額」等を抽出する
3. 売上管理シート側で、PDFの集計期間に対応する「対象月」かつ「ステータス=決済完了」の
   行を集計する(件数・合計金額)
4. 両者を突き合わせ、一致/差異を実行ログ(コンソール)に出力する

現時点では**月次サマリー単位の突合**のみを行い、結果は実行ログへの出力のみです
(シートへの書き込みや通知は行いません)。

## 突合ロジックの詳細

収納明細書の「合計」行には以下の列があり、本ツールはこの値を使います。

| 列 | 意味 | 使い方 |
|---|---|---|
| 売上/与信件数・売上金額 | 期間中の総売上 | 参考値として保持 |
| 返金/与信取消件数・返金金額 | 期間中の返金等 | 参考値として保持 |
| **合計件数・合計金額** | 決済処理金額(純額) = 売上 − 返金 | **突合対象** |
| 手数料 金額/税込金額 | 決済代行手数料等 | 参考値として保持 |
| お振込金額 | 最終振込額 | 参考値として保持 |

シート側は、対象シート(`CONFIG.TARGET_SHEET_NAME`、既定値 `契約一覧`)から
`対象月` が明細書の集計期間に対応する月(例: `2026年08月`)かつ
`ステータス` が `決済完了` の行を抽出し、`合計` 列を合算します。

この「シート側の合計」と「PDFの合計金額(決済処理金額)」を比較し、
件数差・金額差を実行ログに出力します。

## 既知の制限(重要)

実データで検証したところ、**初回実行時点では意図的に差異が出ます**。理由は次の通りです。

- シートの「対象月」はサービス提供対象月(いつの分のサービス利用料か)を表しており、
  実際にカードで決済処理された月(収納明細書の集計期間)とは必ずしも一致しません。
  無料期間明けの初回課金や、返金・与信取消のタイミングによって数ヶ月ずれることがあります。
- 例えば2026年08月分の収納明細書では、決済処理金額(合計)は¥69,102(9件相当)ですが、
  シート上で「対象月=2026年08月」かつ「決済完了」の行は3件・¥23,034 しかありません。
  これはシートの他の行(対象月が07月や09月など)が実際には8月に決済処理されているためです。

この制限に対応するには、シート側に「決済処理日」または「決済処理月」を表す列を
追加してもらい、`SheetReader.gs` の `summarizeByMonth` の条件をその列に変更するのが
確実です。現状は「対象月」列で近似しているため、運用しながら精度を確認し、
必要であれば突合条件を調整してください。

`test/reconcile.test.js` にこの既知の差異を再現するテストがあり、実データでの
挙動を確認できます。

## ファイル構成

```
appsscript.json          GASプロジェクトのマニフェスト(Drive API有効化など)
.clasp.json.example      clasp設定のテンプレート(実際のscriptIdに書き換えて .clasp.json として使う)
src/Config.gs            設定値(PDFフォルダID・対象シート名・完了ステータス文字列)
src/Utils.gs             金額パース・日付フォーマット等の共通関数
src/PdfParser.gs         PDF→テキスト変換、テキストから集計値を抽出する関数
src/SheetReader.gs       シート読み込み・対象月別サマリー集計
src/Reconcile.gs         PDF側とシート側の比較・レポート整形
src/Code.gs              カスタムメニュー(onOpen)とメイン処理(runReconciliation)
test/                    Node.js (node --test) によるロジックのユニットテスト
```

`src/*.gs` の純粋関数(`parseStatementSummary` / `summarizeByMonth` / `reconcile` /
`formatReconcileReport` / `Utils.gs` の関数群)はGASのグローバルAPI
(`DriveApp` 等)に依存しないため、Node.js から直接テストできます。
GAS依存のI/O関数は `extractTextFromPdf` / `readSheetRows` / `findTargetSheet` /
`runReconciliation` / `onOpen` のみです。

## セットアップ

### 1. 前提

- [clasp](https://github.com/google/clasp) がインストールされていること (`npm i -g @google/clasp`)
- 対象のGoogleアカウントでApps Script APIが有効化されていること
- Google Cloud Console側で **Drive API** が有効化されていること
  (Apps Scriptの「サービス」からDrive advanced serviceを追加した場合、
  紐づくGCPプロジェクトでのAPI有効化も必要です)

### 2. スクリプトのひも付け

代理店売上管理シートに直接バインドされたApps Scriptプロジェクトを使う場合:

```bash
clasp login
# スプレッドシートの「拡張機能」→「Apps Script」からスクリプトIDを確認し、
# .clasp.json.example を .clasp.json にコピーして scriptId を書き換える
cp .clasp.json.example .clasp.json
clasp push
```

新規にスタンドアロンのスクリプトを作る場合は `clasp create --type sheets --parentId <スプレッドシートID>` 等で作成してください。

### 3. CONFIGの設定

`src/Config.gs` を編集し、以下を実際の値に合わせてください。

- `PDF_FOLDER_ID`: 収納明細書PDFをアップロードするDriveフォルダのID
- `TARGET_SHEET_NAME`: 突合対象のシート(タブ)名
  (`対象月` / `ステータス` / `合計` 列を持つ契約単位の台帳シート)
- `COMPLETED_STATUS`: 「決済完了」を表す文字列(シートの実際の表記に合わせる)

`TARGET_SHEET_NAME` に一致するシートが見つからない場合は、
`対象月` / `ステータス` / `合計` の3列をすべて持つシートを自動で探索します。

### 4. 実行

1. スプレッドシートを開き直す(カスタムメニューを表示するため)
2. メニュー「売上確認」→「収納明細書と自動照合」を実行
3. 初回実行時は権限承認ダイアログが出るので許可する
4. 実行完了後のアラートに簡易サマリーが表示される
5. 詳細は Apps Script エディタの「実行数」(実行ログ)で確認する

## テスト

ロジック部分(PDFテキスト解析・シート集計・突合)はNode.jsのテストランナーで検証できます。

```bash
npm test
```

`test/fixtures/statement-202608.txt` は実際の収納明細書PDFから抽出したテキストの
サンプルで、`test/fixtures/sheet-rows-202608.json` は対応する売上管理シートの行の
サンプルです。実データでの突合結果(既知の差異を含む)は
`test/reconcile.test.js` で確認できます。
